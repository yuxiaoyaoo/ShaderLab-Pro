# Visual/Sound 分域 Runtime 与 M6 导出事务

M6 把 WebGL Runtime 重构为 Visual 多 Pass 原子 candidate 和独立 Sound snapshot，并为 Graph、纹理、uniform、Pass Graph 与媒体导出增加分域门禁。Runtime 的双向失败隔离成立，rejected candidate 也不会被 successful revision 当成当前内容。App 尚未完成同样的分域：全局 revision/status 会让无关域修改使当前域及其导出 ticket 失效，禁用 Graph 的诊断和 uniform 也可能继续进入活动域门禁。格式需求映射和持续校验点覆盖 PNG/GIF/WAV/MP4/WebM，但建立在这个全局 revision 上。

Watch for: **confirmed** — Sound-only 修改会取消 Visual-only 导出，反向也会取消 WAV；**confirmed** — 已禁用 Graph 的纹理错误或 accepted uniform 仍可阻断活动 Visual；**confirmed** — `verify-m6` 未覆盖 App 编排，也未完整证明并发 Sound snapshot 生命周期。

**Verdict**: NEEDS_CHANGES

## High-level view

Runtime 分别准备 Visual 与 Sound candidate，再按各自结果提交。Visual candidate 包含 Image、所有启用 Buffer、timing plan、纹理和 uniform，任一 Visual Pass 失败都会回滚整个 Visual cohort；Sound 使用独立 program/channel/uniform/texture snapshot，Sound 失败不会替换其 LKG，也不会阻止 Visual commit。

App 的请求门禁按 pass/domain 过滤 Graph compiler、Pass Graph、uniform 和 Runtime diagnostics，successful revision 也能阻止旧 LKG 冒充当前内容。但所有编辑仍推进同一个 `runtimeSetupRevision`，同时把 Visual 与 Sound status 置为 pending，导致 UI、eligibility 和长时间导出重新退化为全局事务。

Graph 编译 cohort 使用 `enabledGraphPasses()`，纹理规划、accepted Graph uniform 汇总和 candidate artifact 合并却遍历全部 Graph editor。禁用 Buffer 后 editor 仍保留，因此不参与 Runtime 的 Graph 仍能产生阻断诊断或 uniform 冲突。

PNG/GIF 和无声 MP4/WebM 只要求 Visual，WAV 只要求 Sound，带音频 MP4/WebM 要求两域；帧/音频 batch 与最终落盘前都会复验 ticket。单一全局 revision 仍会让 ticket requirements 之外的域使 ticket 失效。

`verify-m6` 通过并覆盖 Runtime 双向 failure matrix、missing asset fail-closed 和多个 Sound LKG 字段。它没有驱动 App coordinator，也没有覆盖 retained Sound snapshot 在异步渲染中被新 snapshot 替换后的资源寿命。

## Runtime 的 Visual 原子 candidate 与 Sound snapshot

`ShadertoyRuntime.compile` 分别 prepare 两个域，只提交非空 candidate。Visual candidate 一次性持有全部 program、feedback/preview buffer、texture、timing plan 和 uniform map；Sound candidate 封装 program、texture channels、uniform map 和独立 texture handles（`src/shadertoy/runtime.ts:624-649`）。

```text
RuntimeSetup
   ├─ prepareVisual(Image + enabled Buffers + Pass Graph + textures + uniforms)
   │       └─ one commit or no Visual commit
   └─ prepareSound(mainSound + sound textures + sound uniforms)
           └─ independent commit or retained Sound LKG
```

Sound 渲染 retain 当前 snapshot，新 commit 只 retire 旧 snapshot，retain count 归零后才释放资源（`src/shadertoy/runtime.ts:965-1011,1530-1597`）。`setupBuilder` 保留无法解析的声明纹理 channel，让 Runtime 拒绝对应 candidate，而不是用 dummy texture 伪装成功（`src/shadertoy/setupBuilder.ts:55-68`）。

## 全局 revision 抵消 App 的双向分域

**confirmed** — 任意修改都会递增同一个 `runtimeSetupRevision`，并同时把 `compileState` 与 `soundCompileState` 置为 pending（`src/App.tsx:745-750`）。`currentExportInput` 虽按 requirements 选择 successful lane、diagnostics、Graph artifacts 和 source hash，却仍把全局 revision 放入所有 ticket（`src/App.tsx:533-576`）。

Sound 源码、Sound Graph 或 Sound-only 参数变化会立即使 PNG、GIF、无声 MP4/WebM ticket 失效，即使 Visual 内容未变；纯 Visual 修改也会取消 WAV。普通 eligibility 也会在重编译期间阻断未变化的另一域。应维护 Visual/Sound 各自的 setup revision 和 status，只让 Common 或实际共享资源同时推进两域；ticket 应冻结 requirements 对应的 lane revision。

## 禁用 Graph 仍污染活动域门禁

**confirmed** — `texturePlan` 和 `acceptedGraphUniforms` 遍历 `ALL_GRAPH_PASS_IDS`（`src/App.tsx:404-454`），而 `setPassEnabled(false)` 不移除 editor 或 accepted artifact。禁用 Buffer Graph 的 missing texture 仍进入 `unifiedDiagnostics`；其 generated uniform 也仍进入 `visualUniformContract` 和 candidate setup，可与活动 Image/Common uniform 冲突并使 `requestVisual` 为 false。

这会让禁用有问题的 Buffer 后仍无法恢复 Image 预览或 Visual 导出，尽管 `buildRuntimeSetup` 已不发送该 Buffer。纹理规划、accepted uniform 汇总、candidate artifact 合并和导出诊断应使用同一 enabled-domain pass 集合；禁用 Graph 可保留 authoring 状态，但不能参与 Runtime acceptance。

## 格式 ticket 与 lane 状态

`ExportDialog` 的格式到 requirements 映射正确，并把 validator 传入帧/音频循环，在写文件前再次验证（`src/components/ExportDialog.tsx:135-195,210-350`）。

**confirmed** — 另一个域触发全局 revision 后，`guardCancelled` 会把 ticket 失效当作普通取消；PNG 会保留此前已写出的合法前缀并以成功态“已取消”结束。修复 lane revision 后仍应区分用户取消与 stale ticket，后者应报告失效原因。

Rejected Runtime candidate 不更新对应 successful revision，Graph state 也保持 `stale`，所以 export eligibility 不会把旧 LKG 当成当前内容。**confirmed** — 两个 code-lane status 仍被同步置为 pending/compiling/ready，项目级 `errCount` 也会让活动 Visual 状态栏显示 Sound 错误，反向亦然（`src/App.tsx:529,745-756,1035-1038`）。状态栏和诊断计数应按当前 pass/domain 投影，同时保留全项目 Diagnostics Pane。

## `verify-m6` 对 Sound LKG 的证明边界

failure matrix 在 bad Sound shader 和 missing Sound asset 后检查旧 Sound program、texture handle、uniform 与 `iChannelResolution`，也覆盖 bad Visual/good Sound、`sound:false` 保留和显式空 Sound 清除（`scripts/verify-m6.mjs:673-753`）。

**confirmed** — verifier 没有在 `renderAudio` yield 期间提交新 Sound candidate，未证明 retained/retired snapshot 在最后一个消费者结束前可用并随后释放；也未在拒绝后断言 Sound sampler filter/wrap 或旧资源未提前删除。它直接测试 Runtime 与纯 `exportEligibility`，没有覆盖 App 的全局 revision、禁用 Graph 泄漏和五种格式的 coordinator 行为。应增加 App coordinator 的纯状态测试，以及并发 render/commit、sampler identity 和资源释放断言。
