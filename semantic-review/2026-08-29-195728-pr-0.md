# 结构化 Chat 错误、产品 notice 与双语渲染

本次变更把 10 个 Chat IPC command 的失败面统一为 `{ code, params?, raw_detail? }`，并把生成、编译、渲染、自动文档和模板采用等产品摘要迁移为前端按 locale 渲染的 notice。Chat 消息保存 descriptor/notices，模板难度改为 canonical ID 并兼容旧中文值。当前仍有三个行为缺口，会造成错误摘要或绕过本地化边界。

Watch for: **confirmed** `chat.notice.code-generated` 可能报告“0 行”或修复前的行数；**confirmed** glslang/GPU unavailable 原因仍通过 `note`/`unavailable_reason` 直接显示而不是只存在 `raw_detail`；**confirmed** `compile`/`render` phase ID 在中文 UI 中原样显示。

**Verdict**: NEEDS_CHANGES

## High-level view

Rust IPC rejection 已统一为稳定 code，前端 helper 也会保留后端 code 并为旧式 rejection 补命令 fallback。**confirmed** 成功响应中的环境失败原因仍留在旧 validation DTO 字段，绕开了同一套 raw-detail 约束。

产品摘要由 extractor、pipeline 和模板采用路径生产，再由 ChatPanel 按当前 locale 格式化。**confirmed** 生成摘要在验证/自动修复前创建，因此描述的是初始模型响应而不是最终候选，并会把缺失 code 的 generate 响应说成“已生成 0 行”。

Chat descriptor/notices、模板展示和 difficulty 搜索都会随 locale 重算。**confirmed** 错误反馈的 canonical phase 值没有映射，中文界面仍显示英文内部 ID。

<summary>Issues (3)</summary>

1. **Medium · 生成行数取自初始响应（confirmed）** — code 缺失时会显示“已生成 0 行”，自动修复后也可能显示旧行数；应在 `final_code` 确定后构造 notice，缺少 code 时不发成功 notice。
2. **Medium · unavailable 原因绕过 raw_detail（confirmed）** — glslang/GPU 原因从 `note`/`unavailable_reason` 直接进入 UI；应转为 raw-detail descriptor 经 formatter 展示，或只保留本地化 skipped notice。
3. **Low · feedback phase 未本地化（confirmed）** — `compile`/`render` 内部 ID 被直接渲染；应映射已知 phase ID 并补齐 render 的中英文 key。

</details>

## 生成 notice 与最终候选代码脱节

**confirmed** `process_turn` 在初始模型响应后立即调用 `response.product_notices()`（`src-tauri/src/agent/pipeline.rs:145-146`），但自动修复可能随后替换 fragment，最终代码直到 `src-tauri/src/agent/pipeline.rs:386-390` 才写回。因此 `chat.notice.code-generated.lines` 会保留修复前的行数。

`Intent::Generate` 即使没有 code 也会产生 `lines: 0` 的成功 notice（`src-tauri/src/agent/extractor.rs:312-319`），随后 pipeline 在 `Generate + code=None` 分支直接返回（`src-tauri/src/agent/pipeline.rs:149-161`）。应在 `final_code` 确定后生成或更新该 notice，并在 code 缺失时不发成功摘要。

## unavailable 原因绕过结构化原文字段

**confirmed** 工具不可用路径把原始原因放进 `ValidationView.note`（`src-tauri/src/agent/pipeline.rs:279-285`、`317-324`）和 `RenderReport.unavailable_reason`，ChatPanel 又把它们直接用于 badge title 和本地化前缀后的正文（`src/components/ChatPanel.tsx:101-110`、`159-174`）。glslang 探测文本和 wgpu/OS 原因因此不在 `raw_detail` 中，并与本地化的 `chat.notice.render-skipped` 重复展示。

技术原因若需要展示，应转为明确的 raw-detail descriptor 并经过 formatter；否则只展示 skipped notice，把原文留在日志或诊断数据中。

## compile/render phase 仍作为 UI 文本

**confirmed** pipeline 生成的 `ErrorFeedback.phase` 是内部值 `compile` 或 `render`（`src-tauri/src/agent/pipeline.rs:291-296`、`349-354`），ChatPanel 仅在 phase 为空时使用翻译 key（`src/components/ChatPanel.tsx:535-539`）。正常后端路径因此绕过翻译，在中文 UI 中显示英文 ID。

应映射已知 phase ID，并为 render 增加中英文 key；未知模型值仍可作为模型原文保留。
