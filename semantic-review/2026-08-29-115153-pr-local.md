# M6 图资源、Graph Library、SDF/Sound 与持久化链路

这组变更把 Graph authoring 扩展到内容寻址纹理、项目级 Node Library、Texture2D、SDF/Raymarch 和 Sound，并把资源接入项目保存、Autosave、Runtime 与 GraphResourcesDialog。实现采用规范化 JSON revision、raw-byte SHA-256、按 asset+sampler 分配 iChannel、强类型 Group AST、受限 Custom Function 表达式，以及视觉/Sound 分开的 Runtime 接受结果。主路径和既有 M0–M5 回归均通过，但拒绝路径仍会破坏 Sound last-known-good，资源保存没有覆盖二进制事务边界，部分声称的强类型和 authoring 能力也没有闭环。

Watch for: **P1 · confirmed** Sound 验收仍被视觉和全 Graph cohort 双向耦合，且 Sound 拒绝后旧 program 会使用新 channel/uniform 状态；**P1 · confirmed** 纹理二进制在文本事务前原地覆盖，后续失败可损坏原项目；**P1 · confirmed** Custom Function 只做 token 白名单、不校验表达式类型；**P1 · confirmed** Node Group 在产品 UI 中只能插入固定 starter，界面声称的选择封装不存在；**P2 · confirmed** Autosave 内嵌资源与 metadata revision 漂移，scratch Autosave 写入失败仍报告成功；**P2 · likely** 未受限的图片 payload/解码尺寸可造成资源耗尽。

**Verdict**: NEEDS_CHANGES

## High-level view

**confirmed** Sound 的独立接受只覆盖“Sound shader 失败时保留旧 program”。App 在进入 Runtime 前仍要求所有 Graph 同时通过编译，Runtime 又让视觉失败或 Sound channel plan 失败终止整个 setup；即使只有 Sound GLSL 被拒绝，旧 Sound program 也会和候选 options、uniforms、textures 混用。

**confirmed** 项目文本使用带 rollback 的多文件提交，但 Asset bytes 通过另一个非原子命令提前写入。文本或二进制写入失败后，旧 manifest 可指向已被覆盖或截断的文件。

**confirmed** Autosave 保存 Manifest、payload 和 Library，却只重算 Pass Graph reference；恢复端不验证 metadata 中 Asset Manifest/Graph Library revision 与内嵌资源一致。scratch 路径还会吞掉 localStorage 写入失败并返回成功。

**confirmed** Node Group 的 AST 类型推导、引用检查和无递归 DAG 已存在，但 GraphResourcesDialog 没有任意 Group 的创建/编辑入口。verify-m6 直接构造 nested Group，未覆盖用户 authoring 流程。

**confirmed** Custom Function 的 token 白名单限制了语句和未知标识符，但显式签名没有参与表达式类型检查。Library normalization 和 Graph compiler 会接受类型不匹配的 helper，把错误推迟到 WebGL Runtime。

**likely** 资源边界允许最高 32768×32768 的声明尺寸，没有 payload byte、总像素或项目总资源预算；实际尺寸只在 createImageBitmap 完成后检查。不受信任项目或高压缩图片可在校验失败前消耗大量 CPU/内存。

## Sound 独立接受没有形成完整的子事务

**P1 · confirmed.** `src/App.tsx::compileGraphCohort` 用单个 `graphCompileFailed` 汇总视觉与 Sound Graph；任何 pass 的 Graph compiler 失败都会在调用 Runtime 前返回，所以坏 Sound 会阻止合法视觉候选，坏视觉也会阻止合法 Sound 候选。`src/shadertoy/runtime.ts::compile` 又先编译全部视觉 pass，并把 Sound channel plan 错误放进同一个 `uniqDiags`；视觉失败或仅 Sound channel 无效都会返回 `{ ok: false, soundOk: false }`，与接口注释承诺的 independent acceptance 不一致。修复应把 Graph compiler cohort 和 Runtime setup 拆成视觉、Sound 两个独立 candidate/result 事务，或让一次 compile 分别提交 `visualOk`、`soundOk`，且一个子事务的 preflight 不能取消另一个。

**P1 · confirmed.** Sound shader 被拒绝时，Runtime 保留 `this.soundProg`，但随后无条件提交候选 setup 的 `this.options`、`this.uniformVals` 和整组 texture assets。`renderAudio` 通过 `bindChannels('sound', 'image')` 读取这些新 options，因此旧 program 不再运行在它被接受时的 sampler/slot/uniform 环境。实测先接受 slot 0→A 的 Sound，再提交会失败且改为 slot 0→B 的候选，第二次返回 `ok: true, soundOk: false`，随后旧 program 的 audio draw 绑定 B。修复需要把 Sound program、channels、所需 uniform contract/values 和资源 identity 作为同一个 LKG snapshot 原子替换；拒绝时全部保留旧 snapshot。

## Asset bytes 绕过项目原子提交

**P1 · confirmed.** `src/project/projectIO.ts::saveProjectTo` 在 `writeTextFilesAtomic` 之前逐个执行 `writeBinaryFile`，而 `src-tauri/src/lib.rs::write_binary_file` 使用 `std::fs::write` 原地写目标。覆盖已有项目时若任一后续 asset、Graph/GLSL 文本或 shaderlab.json 提交失败，旧 metadata/manifest 会保留，已写 asset bytes 却不会回滚；单个 `fs::write` 中途失败还可能先截断旧文件。`scripts/verify-m6.mjs` 只断言 binary event 在 text commit 前，没有注入失败并验证旧项目仍可打开。

修复应把 binary 与 text 一起交给 native 多文件事务，以 byte staging、fsync、backup 和逆序 rollback 覆盖全部目标；或使用 SHA-256 内容寻址的新文件名，只写新 blob，成功后原子提交 manifest/shaderlab.json。新增“第 N 个 binary 失败”和“binary 全成、text commit 失败”测试，并在失败后重新打开旧项目验证 Manifest hash、Graph/GLSL 和 bytes 一致。

## Autosave resource identity 与实际可恢复性分离

**P2 · confirmed.** `src/project/projectIO.ts::writeAutosave` 通过 `projectWithPassGraphIdentity` 重算 Pass Graph reference，却在规范化 `assetManifest` 和 `graphLibrary` 后没有更新 `normalizedMeta.assetManifest`/`normalizedMeta.graphLibrary`。`normalizeAutosavePayload` 只验证 Manifest contentHash 与 payload，不交叉校验内嵌资源 revision 和 metadata reference。用 `old-asset`/`old-library` metadata 保存新资源后，读回 snapshot 仍保留旧 revision，而 canonical revision 已改变。修复应在构造 payload 前更新两个 reference 的 file、formatVersion、revision，并让 normalizer 对存在的 reference fail closed；verify-m6 应断言恢复后的 metadata reference 匹配 snapshot 资源。

**P2 · confirmed.** scratch 项目把所有 Base64 纹理序列化到单个 `localStorage` value。`writeAutosave` 捕获 `setItem` 的 quota/availability 异常后仍返回 `{ path: '', savedAt }`，`App.tsx::runAutosave` 随后把它当成成功保存；M6 的二进制 payload 显著扩大了触发面。修复应改用桌面文件/IndexedDB 等 blob 后端，或至少让失败向 App 传播、不记录成功时间；测试应让 `storage.setItem` 抛出 `QuotaExceededError` 并断言失败可见。

## Custom Function 显式签名没有约束表达式类型

**P1 · confirmed.** `src/graph/library.ts::validateCustomExpression` 只验证 token、标识符、括号和调用白名单，没有根据 `LibrarySocket.type` 构建 typed expression，也没有检查结果是否兼容 `fn.output.type`。把 output 声明为 `float`、expression 设为 `vec4(value)` 会通过 `normalizeGraphLibrary`，`compileGraph` 也返回 `ok: true` 并生成：

```glsl
float _sg_custom_bad_signature_v1(float value, float width) {
    return (vec4(value));
}
```

错误直到真实 WebGL 编译才暴露；标量 swizzle、bool 算术和内建函数签名错误也能进入 artifact。修复应把表达式解析为与 Group 共用或等价的 typed AST，对运算符、constructor、swizzle 和白名单函数执行签名推导，并要求结果等价于 output；若保留字符串 DSL，至少在添加/加载 Library 时做独立 GLSL helper preflight，不能让 Graph compiler 报成功。verify-m6 需要返回类型、输入操作数、swizzle 和 built-in shadowing 负例。

## GraphResourcesDialog 只能制造固定 Wave Mix

**P1 · confirmed.** `src/components/GraphResourcesDialog.tsx` 的 Group API 只有 `onAddStarterGroup` 和删除，`src/App.tsx::addStarterGroup` 始终调用 `createStarterNodeGroup`；Graph workspace、selection commands 和其他组件中没有“从选择封装”或任意 Group AST 编辑入口。Dialog 却写着“也可在 Graph 工作区框选节点后封装”，而 `scripts/verify-m6.mjs` 的 nested Group 是直接构造 JSON 后调用 normalizer。强类型、嵌套、版本化 Group 因而只能通过测试或手工修改项目创建。

修复应实现选择边界提取：把内部 DAG 转成 Group expression，按跨边界连接生成强类型 inputs/outputs，选择 id/version 后写入 Library，并以 group node 替换选择；若本轮不包含封装器，至少提供受验证的 Group JSON/AST 编辑或导入入口，并移除未实现文案。验收应从公开 UI 创建 nested Group，保存、重开并编译。

## 不受信任纹理在校验前缺少资源预算

**P2 · likely.** `src/graph/assets.ts::normalizeAssetManifest` 接受单边最高 32768 的纹理且不限制 asset 数量或总像素，`src/graph/contentHash.ts::assetPayloadBytes` 同步复制并 hash 完整 Base64，`src/graph/assetRuntime.ts::decodeTexturePayload` 先执行 `createImageBitmap`、再检查实际宽高。超大或高压缩图片可在 Manifest 尺寸不匹配被拒绝前占用主线程和解码内存；Autosave normalization 也同步处理所有 payload。修复应在 bridge/read 边界设置单文件与项目总 byte 上限，降低并累计 Manifest pixel budget，在解码前读取格式 header 验证实际尺寸，并把 hash/decode 放到 worker 或受限 native 路径；用超限 payload、伪造小尺寸 Manifest 和多资产总预算做拒绝测试。

## verify-m6 未覆盖失败矩阵

**P1/P2 · confirmed.** `npm run verify:m0-m6`、`npm run typecheck`、`npm run build` 与 `cargo test --manifest-path src-tauri/Cargo.toml` 全部通过，但没有覆盖视觉/Sound 任一侧独立失败与完整 LKG、binary/text rollback、Custom Function signature mismatch、真实 UI Group authoring、resource reference equality、storage quota 和 decode budget。补齐这些用例后，acceptance 才与 source 声称的拒绝语义一致。
