# M5 多 Pass Graph 恢复闭环与 Runtime cohort 时序

第二轮改动修复了首轮大部分 M5 契约问题：persisted Graph 使用 resolved channel environment 分类，旧 M3 channels 迁移为稳定 sample endpoint，Code↔Graph 转换保留 resolved 物理槽，Pass Graph identity 也进入 open/autosave 校验。Runtime planner 与 WebGL binder 已共享 texture-index 选择函数，capture 使用独立 buffer set 和目标尺寸原生渲染。当前仍有一个用户可见阻塞：reference identity mismatch 将 Graph 放入只读 recovery 后，编辑 Pass Graph 虽清除 issue，却不会重新激活 editor，cohort、保存和导出无法恢复。全部验证命令通过，但 WebGL flip、preview freeze 和 capture history 仍只验证纯 helper，没有执行真实 executor 生命周期。

Watch for: **[高][confirmed]** identity mismatch 后编辑 Pass Graph 无法把 recovery document 重新激活，Graph 项目仍永久停在 readonly；**[中][confirmed]** current/previous、统一 flip 与 capture history 没有 executor 级回归，真实 WebGL binding/资源切换仍未被自动验证。

**Verdict**: NEEDS_CHANGES

## High-level view

Pass Graph identity 会在 project open 和 autosave recovery 中比较 reference format/revision，并在不匹配时 fail closed。**[高][confirmed]** 恢复出口未闭合：Pass Graph 面板修改只删除 identity issue 和触发 cohort compile，没有把 recovery document 转回 editor state；编译器看不到 Graph candidate，save/export 继续拒绝。

旧 M3 Graph + legacy channels 会按 target authoring 注入确定性 `input.channel-sample`，并保留 slot/filter/wrap；保存把迁移后的 Graph、fallback、Pass Graph 和新 identity 作为同一原子批次提交。Code↔Graph 转换以 resolved slot 为边界，多边和四槽满载不再依赖 auto slot 猜测。

Graph candidate 与 Runtime accepted artifact 保持分离，所有启用 Graph pass 只有在统一 Runtime setup 成功后才共同进入 `effectiveSources`。导出票据冻结 cohort、Pass Graph revision 和 effective source hash；目标尺寸 capture 使用独立 feedback buffers，结束后恢复 preview buffers 和冻结画面。

Buffer/Image current/previous 已由 planner 与 binder 共用 `selectChannelTexture`，关闭两套公式漂移。**[中][confirmed]** `verify-m5` 未实例化 `ShadertoyRuntime`，`bindChannels`、全局 flip、preview target、capture begin/end 和连续 feedback history 仍无 executor 回归。

## Identity mismatch 的恢复出口停在 readonly document

`openProject` 将 `passGraphIdentityValid=false` 传给 `activatePersistedGraph`；后者即使 Graph 在新 resolved environment 下可编译，也会调用 `activateReadOnlyGraphRecovery`，删除该 pass 的 editor state，仅把文档保存在 `graphRecoveryDocuments`（`src/App.tsx:1054-1064`, `549-555`）。

用户随后修复 Pass Graph 时，`updatePassGraph` 只更新文档、过滤 `pass-graph.invalid/reference-*` issue、标记现有 editor pending 并安排 `compileGraphCohort`（`src/App.tsx:959-972`）。它没有用新 resolution/environment 重新分类 `graphRecoveryDocuments`，也没有调用 `activateGraph`。cohort 遍历启用 Graph pass 时发现 `working[pass]` 不存在，设置 `graphCompileFailed` 后返回（`src/App.tsx:586-604`）。

这是 **[高][confirmed]** 的永久恢复阻塞。复现方式：保存合法 channel-sample Graph，修改 `graphs/pass-graph.json` 的 filter/wrap 造成 reference revision mismatch，打开后在 Pass Graph 面板修复到有效 resolution。identity issue 消失，但 Graph 仍没有 editor/accepted artifact；`currentGraphSaveOptions` 以“Graph 处于只读恢复”拒绝保存（`src/App.tsx:1166-1181`），导出也无法形成完整 artifact cohort。应在 Pass Graph 有效后，对仅因 identity mismatch 进入 recovery 的 Graph 重新 classification，原子激活全部成功文档再编译 cohort；失败项保留明确 recovery issue。

## Legacy migration、authoring 转换和 autosave identity 已闭合

首轮 persisted environment 问题已关闭：open/autosave 将 `channelEnvironment` 和 resolved revision 传入分类。旧 M3 Graph target 由 `migratePassGraphFromLegacy` 注入稳定 sample 节点，已有 sample wiring 随 ID 重命名保留，只有 Code target 生成 `code-slot`（`src/project/passGraph.ts:337-403`）。这支持 Image Graph + legacy channels 的 open→edit→cohort→save→reopen；无 reference 的项目作为 migration 标记 resave，而不是 identity mismatch。

Code 新边使用同号 manual slot；Code→Graph 为每条输入建立稳定节点；Graph→Code 从 resolved 结果固化物理 slot（`src/project/passGraph.ts:414-481`）。多边和四槽满载时 endpoint、filter/wrap/timing 与实际 slot 保持一致，无可用 endpoint 时 UI 拒绝操作。autosave 先解析 dirty Pass Graph，再用同一 resolution 写 snapshot meta identity（`src/project/projectIO.ts:382-410`）。

## Candidate acceptance 与目标尺寸导出边界

`acceptedGeneratedSources` 只读取 `runtimeAcceptedArtifact`；`compileGraphCohort` 收齐所有启用 Graph pass 后才构造统一 Runtime setup，任一 Graph、uniform contract 或 Runtime compile 失败都不会提升部分 candidate（`src/App.tsx:565-648`, `src/state/graphEditorStore.ts:31-77`）。

导出票据冻结 Graph generation/revision/sourceHash、Pass Graph revision、effective source hash 和 Runtime revision，并在长导出循环及最终写入前持续校验。capture 暂停 live playback，按请求 width/height 创建独立 buffers，保留 preview ping-pong map 和冻结画面，结束时恢复原 map（`src/components/ExportDialog.tsx:136-198, 203-365`, `src/shadertoy/runtime.ts:387-464`）。

## Shared texture selector 尚无 WebGL executor 回归

`channelTextureRole/selectChannelTexture` 同时服务 `planRuntimeFrame` 和 `bindChannels`；Buffer 在统一 flip 前选择 previous/read 或 current/write，Image 在 flip 后选择 previous/other 或 current/read（`src/shadertoy/channelTiming.ts`, `src/shadertoy/runtime.ts:759-779, 871-891`）。首轮“planner 与 executor 使用两套索引公式”的实现缺口已关闭。

仍有 **[中][confirmed]** 测试缺口：`scripts/verify-m5.mjs` 只调用 `selectChannelTexture`、`captureFrameNeedsReset` 和 `planRuntimeFrame`，未构造 fake WebGL/浏览器 Runtime。`bindChannels` 的 texture/sampler unit、Buffer DAG 实际 draw/flip、Image previous、preview target，以及 `beginCapture/endCapture` 的 framebuffer、尺寸和 ping-pong history 均未执行。应覆盖至少两帧 current/previous matrix、暂停/运行 preview 在 capture 前后的 read index/history、非预览尺寸的 canvas/FBO，以及取消后的恢复。
