# M2 Image Shader Graph 编辑闭环完成

本轮最终 follow-up 修正了 Generated Code 的来源信任边界：存在 Runtime accepted artifact 时始终复制 accepted source，只有不存在 accepted fallback 时才展示并复制未接受的 compiler candidate。界面通过 `generatedSourceAccepted` 区分两种状态，不再把 Runtime 已拒绝的代码描述为稳定版本。原 review 的 11 项问题及验证要求均已闭环，Graph 项目正式文件读写仍按约束留给 M3。

Watch for: 未发现新的阻断性问题；M3 仍需实现 Graph 文件持久化，当前 Save/Save As 会明确阻断且保持 dirty。

**Verdict**: APPROVED

## High-level view

Graph Runtime 协调明确区分当前 compiler candidate、last successful artifact 与 Runtime accepted artifact。外部 Pass 在 Graph invalid/pending 时使用稳定 accepted fallback 重验完整 setup，但 fallback 不会提升为当前 Graph accepted，也不会清除 stale。

Uniform、Inspector、clipboard/fragment、pointer 生命周期、快捷键焦点、节点 bounds、诊断 reveal、创建确认和导出入口已按同一 Graph 状态边界收敛。Generated Code 复制也遵循 accepted 优先规则，无 accepted fallback 时明确标记 candidate 未被 Runtime 接受。

持久化仍停留在 M2 边界：常规 Graph Save/Save As 不会写入指向不存在 Graph 文件的项目元数据，正式 `graphs/image.shadergraph.json` 项目读写没有提前实现。

## Generated Code 的 source 与信任提示已对齐

`selectGeneratedCodeSource()` 始终优先 `runtimeAcceptedArtifact`。只有从未产生 accepted artifact 时才退到 `lastSuccessfulArtifact` 并返回 `accepted: false`，因此 `ShaderEditorWorkspace` 不会再把 Runtime rejected candidate 描述为 accepted source。

`verify:m2` 覆盖“Runtime rejected candidate + accepted fallback”和“无 accepted fallback”，断言 source 与 accepted 标志一致。

## M3 边界与最终验证
