# 结构化 Typed IR 已落地，但全图节点值门禁仍可绕过

这次修复把节点 lowering 改成结构化 Typed IR，并由单独 emitter 生成 GLSL、source map 与成功 artifact；source map 身份和参数 ID 派生的 uniform 名称也已闭合。指定的 `mask=12`、错误 float/vector、不可达坏 literal、stale hash 和 uniform 增量稳定测试均已加入并通过。当前仍有两个节点值契约缺口：自定义 validator 可以替代而不是叠加 socket 类型校验，而且不可达子图不会执行依赖输入类型的 swizzle 校验。当前差异还包含任务明确排除的 App/UI/项目 IO 修改。

Watch for: **confirmed** 自定义 `valueFields` 可让错误 socket 值通过全图验证；**confirmed** 不可达 `vec2 -> swizzle.z` 随成功 artifact 被接受；**confirmed** change set 仍修改 App/UI/项目 IO。

**Verdict**: NEEDS_CHANGES

## High-level view

`buildTypedIr()` 产出包含 uniforms、helpers、bindings 与 output 的 `TypedIrModule`，`emitTypedIr()` 再独立生成 GLSL 和 source map。literal、builtin、uniform、reference、unary、binary、call、construct、convert、swizzle 和 trusted intrinsic 都是带类型与 origin 的判别联合，float 到向量通过显式 `convert` 表达。

成功 artifact、source map 和 compile result 共享 revision、semantic hash 与 source hash；诊断映射在 expected hash/revision 不匹配时回退到 code origin。Uniform emitted name 只由 parameter ID 的可逆编码产生，不受 display name 或其他碰撞参数增删影响。

全图结构阶段会遍历所有节点值，但通用 socket validator 与节点自定义 validator 不是组合关系。类型推导只遍历输出可达节点，因此依赖实际输入维度才能判断的 swizzle 合法性仍会绕过不可达节点门禁。

当前工作树还改动 `src/App.tsx`、`src/components/EditorPane.tsx` 和 `src/project/projectIO.ts`，涉及 runtime source 接入、导出和项目持久化，超出本轮 M1 修复边界。

## Socket 基础校验会被自定义 valueFields 覆盖

**confirmed** `validateNodeValues()` 在 `src/graph/registry.ts:95-97` 通过 `explicit ?? graphValueField(type)` 选择单个 validator。节点定义只要为 float socket 声明始终通过的 `valueFields` validator，持久化的 `"bad"` 就不会再经过 float 类型和 finite 校验；最小自定义 registry 探针返回 `ok: true`、无诊断并生成成功 GLSL。这让公开的可组合 NodeDefinition 契约无法保证全图持久化值符合 socket 类型。

注册时的默认值门禁只遍历 `definition.defaultValues`（`src/graph/registry.ts:113-116`），没有检查 `SocketDefinition.defaultValue` fallback。省略 `defaultValues` 但声明错误 socket fallback 的定义可以注册成功，失败会延迟为 `compiler.internal`，而不是稳定的 schema/graph validation 诊断。通用 socket 类型校验应始终先执行，自定义字段校验只追加更窄约束；注册时还应验证每个声明的 socket fallback。

## 不可达 swizzle 的分量越界不会阻止成功 artifact

**confirmed** `buildTypedIr()` 在 `src/graph/compiler/index.ts:216-217` 先把拓扑序过滤为 Fragment Output 可达节点，然后才调用 `inferTypes()`。`vector.swizzle` 的分量范围检查依赖 `inputTypes.value`（`src/graph/nodes/vector.ts:72-79`），所以不可达的 `vector.combine2 -> vector.swizzle(mask: "z")` 不会执行该检查；最小探针返回 `ok: true` 且无诊断。

持久化边已把 swizzle 输入固定为 vec2，`z` 对该输入必然越界。当前测试只覆盖可达的 `z`/`xrrr`、语法错误的 `mask=12` 和不可达错误 float，未覆盖“语法合法但依赖输入后非法”的不可达配置。应对完整拓扑执行类型推导/节点语义校验，仅把 binding lowering 和 GLSL emission 裁剪到可达子图，并加入该回归用例。
