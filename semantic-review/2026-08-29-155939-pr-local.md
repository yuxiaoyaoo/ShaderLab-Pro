## High-level view

Graph 文档、生成 GLSL 与 Runtime accepted artifact 被明确分层，项目 Pass Graph 负责 Buffer 拓扑和 timing；Graph cohort 只有在同一 library/environment identity 下被 Runtime 接受后才可保存或导出。Visual 与 Sound 使用独立的编译状态、成功 revision 和 last-known-good 路径。

项目持久化把 Graph 文档、Pass Graph、纹理 manifest/payload、Graph Library 和 workspace 状态纳入原子事务与 autosave v2。异步 autosave 绑定发起时的 project identity、目录和名称，项目替换和另存为会推进 identity 并清空旧 checkpoint 状态。

Shadertoy 完整包使用 `{ visual: true, sound: soundEnabled }` 的专属 requirements，ticket 覆盖所需域 revision、完整 effective source hash、Graph cohort 与 Pass Graph revision。serializer 目前只表达 Buffer input，因此两个完整包入口统一拒绝 Graph Texture2D 和 Code 本地 texture channel；EditorPane 的按钮状态、提示和执行也使用同一专属 eligibility。

其余差异建立 Graph compiler/editor/state 栈、Visual/Sound 分域 Runtime、资源与 Library 迁移，并扩展 Rust agent 的 GLSL 编译、离屏渲染、模板检索和混合文本/二进制原子写入。

## Runtime accepted Graph cohort 与 Visual/Sound 分域门控

Graph semantic generation、library revision、Pass Graph/environment revision 和 source hash 共同标识可持久化 cohort；布局编辑不会推进 semantic generation，过期编译结果不能覆盖新状态，无法重建相同 identity 的持久化 Graph 会进入只读 generated-GLSL fallback。保存、转 Code 和导出因此消费已被 Runtime 接受的 artifact，而不是竞争中的最新 Graph。

Visual 与 Sound 各自维护 setup revision、成功 revision、诊断和 accepted artifact。完整媒体或 Shadertoy 包声明两域需求，单 pass fragment 只声明当前域；`validateExportTicket` 按捕获时的 requirements 重建 ticket，既不让无关域变化误杀单域导出，也不让完整包漏验另一域。

## Autosave checkpoint 与发起项目绑定

**confirmed** — `runAutosave` 在调用 `writeAutosave` 前捕获 `projectIdentity`、`projectDir` 和 `projectName`，await 返回后逐项与当前值比较；任何一项变化都不更新 `autosaveInfo`，也不调用 `persistSession(false)`（`src/App.tsx:1983-2012`）。`applySources` 覆盖新建、模板、打开、Shadertoy 导入和恢复等项目替换路径并推进 identity，另存为成功后也推进 identity；`advanceProjectIdentity` 同时清空旧 checkpoint（`src/App.tsx:367-371,1438-1447,1821-1825`）。重命名期间则由 name guard 拒绝旧请求。用户提供的 `autosave-project-race pass=true` 动态证据覆盖 deferred autosave 在项目切换后的完成顺序。

## Shadertoy 整包使用完整 Visual + enabled Sound ticket

**confirmed** — `shadertoyExportRequirements` 固定要求 Visual，并仅在 Sound 启用时追加 Sound；专属 eligibility 捕获两个域的成功 revision、相关诊断、Graph artifacts 和同时包含 visual/common/buffers/sound 的 effective source identity（`src/App.tsx:608-679`）。顶层入口写入前按相同 requirements 重验；EditorPane 通过 `captureShadertoyExportTicket` 获得同一 ticket，并在文件夹选择返回后重验（`src/App.tsx:1912-1937,3021-3027`; `src/components/EditorPane.tsx:143-159`）。活动 pass 的单域 ticket 只用于 `.frag`。用户提供的 `Shadertoy Sound invalid/valid gate pass=true` 覆盖启用 Sound 时的负向与正向门控，仓库 `verify:m6` 也验证分域 revision 和双域 eligibility。

## Graph 与 Code 本地纹理在两个入口统一 fail-closed

**confirmed** — `shadertoyRepresentationIssue` 遍历所有启用的 Image/Buffer/Sound pass：Graph authoring 的 resolved texture environment 只要含资产就阻塞，Code authoring 的 metadata 只要含 `type:'texture'` channel 也阻塞（`src/App.tsx:664-678`）。顶层入口在打开目录选择器前检查；EditorPane 的 provider 在序列化时再次检查，专属 ticket capture 在 guard 存在时也返回空。因此 Buffer-only `toShadertoyJson.attachInputs` 不会收到不可表示项目，也不会成功生成引用本地 `iChannelN` 却缺 input 的 JSON。用户提供的 `Code texture gate pass=true` 覆盖 Code 路径；Graph guard 使用的正是生成 Texture2D GLSL 时分配的 `texturePlan().environments[pass].assets`。

## EditorPane 的 Shadertoy 按钮与执行路径共享专属状态

**confirmed** — App 传入 `canExportShadertoy={!representationIssue && packageEligibility.eligible}`、专属 blocked reason 和专属 ticket capture，`ShaderEditorWorkspace` 原样透传（`src/App.tsx:3021-3027`; `src/components/ShaderEditorWorkspace.tsx:53-58,99`）。菜单项的 `disabled`、`title` 和点击处理优先读取这些专属 props（`src/components/EditorPane.tsx:143-159,313-323`），不再回落到活动 pass gate。
