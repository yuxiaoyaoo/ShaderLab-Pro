# M3 Graph 恢复边界与原子保存修复收口

本轮关闭了上一报告的四个问题：compiler-invalid 或首次被 Runtime 拒绝的持久化 Graph 转入只读 generated GLSL 恢复；项目边界拒绝非 Image Graph；提交后的 backup 清理不再反转成功语义；Rust 增加真实多文件故障注入回滚。missing、corrupt 和 compiler-invalid Graph 的 fallback 若再被 Runtime 拒绝，会尝试隔离的安全占位 shader，Autosave 也保留只读恢复中的原始 Graph。M2 accepted artifact 的 stale-preview 契约未回归，类型检查、M2/M3 验证、构建和 Rust 测试全部通过。剩余两项是非阻塞测试深度缺口。

Watch for: **confirmed（non-blocking）** — App 级恢复时序没有模拟“候选拒绝 → fallback 拒绝 → 安全占位”的集成测试；**confirmed（non-blocking）** — 原生故障注入未直接覆盖最终 `shaderlab.json` 提交失败或 post-commit backup 删除失败。

**Verdict**: APPROVED

## High-level view

持久化 Graph 经过 schema 与 compiler 两层分类。编译失败的文档保留诊断和 Autosave，但只运行项目内 generated GLSL；可编译文档首次 Runtime 验收失败时也进入该模式，而普通编辑失败继续展示 M2 已接受 artifact。

missing、corrupt、compiler-invalid 与首次 Runtime rejected 都先尝试 persisted fallback，失败后改用无 Buffer、无 channel、空 Common 的安全 shader，避免沿用上一项目画面。独立 recovery document 让不可编辑的原图仍可进入 Autosave。

项目格式能力已收窄到 Image Graph。非 Image Pass 的 Graph authoring 在 normalization/open boundary 直接失败，不再形成 App 无法保存和门控的部分支持状态。

原子写入维持 `shaderlab.json` 最后提交；中途失败逆序恢复真实文件。全部替换完成后的 backup 清理失败只告警并返回成功，使 App/Autosave 状态与磁盘结果一致。

## Persisted Graph 的只读恢复与 M2 accepted preview

`parseProjectGraph` 保留 schema-valid 文档，`inspectPersistedGraph` 追加 compiler diagnostics，`classifyPersistedGraph` 决定是否进入编辑器。缺 Fragment Output、循环等 compiler-invalid 文档由 `activateReadOnlyGraphRecovery` 保存原文档并让 `effectiveSources` 回落到 persisted generated GLSL。

可编译 persisted Graph 以 `loadedGraphPendingRuntimeRecovery` 标记首次 Runtime 验收；候选被拒绝且尚无 accepted artifact 时切换只读恢复。已有 accepted artifact 时 `loadedGraphRuntimeAction(true, false)` 保持 normal flow，后续语义编辑失败仍使用 M2 stale-preview，不会降级为磁盘 fallback。

`verify:m3` 覆盖 missing-output、cycle 的编译诊断、只读分类和 persisted source；`verify:m2` 覆盖语义编辑后 accepted artifact 保留、旧 revision 不得成为当前 artifact，以及 rejected candidate 回退 accepted generated source。

## generated GLSL 被拒绝后的安全占位

只读恢复使用 `sources.image` 的 persisted generated GLSL。若 Runtime 拒绝，`safeGraphRecoverySetup` 清空 Image channels 和 Common、禁用 Buffer/Sound，并编译固定 `SAFE_GRAPH_RECOVERY_SHADER`。missing/corrupt Graph 虽没有 recovery document，仍保留 Graph authoring 与 persisted image source，因此进入同一 fallback/safe-placeholder 分支；compiler-invalid 与 Runtime rejected 还保留原文档和节点诊断。安全 shader 若也失败，会产生 `graph.recovery-placeholder-rejected`，不会报告可信预览。

**Low — confirmed.** `verify:m3` 只断言 `graphRecoveryPreview(false) === "safe-placeholder"` 和 Runtime action 决策，没有运行 App 的异步编译编排，也未覆盖 Runtime 延迟就绪下的 missing/corrupt 恢复。增加带 fake Runtime 的协调测试，锁定候选、fallback、安全占位三次 setup 与诊断结果。

## Autosave 保留 recovery Graph

`runAutosave` 选择 `graphEditor()?.document ?? graphRecoveryDocument()`；compiler-invalid 或首次 Runtime rejected 的只读恢复因此保存原始 Graph，同时 `effectiveSources` 保存 persisted fallback。恢复时快照重新经过 parse、compiler inspection 与分类。

`verify:m3` 写入 missing-output Graph 的 Autosave V2，重读后确认 Graph 与 generated GLSL 均保留，并再次得到 `readonly-recovery` 和 `graph.output-count`。真正 missing/corrupt 的 Graph 没有文档可序列化，快照仍保留 fallback source 与 Graph authoring 元数据，恢复后只能显式 Detach to Code。

## 非 Image Graph 在项目边界 fail closed

`normalizeAuthoring` 对 `common`、`bufferA-D`、`sound` 的 Graph authoring 直接抛错，`GRAPH_PASS_IDS` 同时缩为 `image`。`verify:m3` 逐项断言 parse 拒绝，并验证 `openProjectFrom` 在读取 Pass 文件前拒绝 Buffer Graph；1.0 migration 仍明确迁移为 Code。

## 原子提交的成功边界与真实文件回滚

`write_text_files_atomic_impl` 在目标旁 staging 并 `sync_all`。第二项提交故障注入在真实临时目录确认已替换 Graph 恢复、当前 GLSL backup 恢复、未提交 meta 不变且 sidecar 清理；混合测试确认新建 Graph 被移除、已有目标恢复，独立 rollback failure 测试确认失败 backup 保留。

全部目标提交后，backup 删除错误仅写 stderr 并返回 `Ok(())`，因此 App 会采用 normalized meta、清除 dirty，Autosave 也不会把已落盘批次当作失败重试。

**Low — confirmed.** 多文件测试只传入 `Some(1)`；没有用 `Some(2)` 覆盖 Graph 与 GLSL 已提交后最终 commit marker 失败，也没有注入 backup 删除失败来锁定 post-commit `Ok`。实现使用同一逆序循环处理任意 index，未见索引分支，但应为这两个关键成功边界增加直接回归测试。
