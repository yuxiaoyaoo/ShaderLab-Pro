# M5 Pass Graph 恢复、持久化与真实 WebGL 回归闭环

本轮关闭了上一报告的四个主体缺口：identity planner 在同一 candidate revision 下联合分类 editor/recovery 且只提升 identity-mismatch，disabled Graph 以 exact environment 编译 authoring artifact 后可完整保存重开，runtime-rejected 不再因无关 Pass Graph 编辑被提升，fake executor 也真实执行同一 capture session 的 frame 0→1。首轮五项——channel Graph 重开、旧 M3 channel migration、Code↔Graph endpoint/slot、Pass Graph reference identity、真实 WebGL texture/flip——及 candidate/effectiveSources、原子保存、preview freeze/native target size 均通过回归。最终仍有三个状态生命周期缺口：旧 topology issue 在合法编辑后可能残留，空/部分 enabled cohort 会误清 disabled Graph 的首次 Runtime recovery 标记，Autosave 不保存 runtime-rejected reason。全部自动验证通过，但这些 App 级路径没有相应集成覆盖。

Watch for: **[中][confirmed]** 合法 Pass Graph candidate 只清除 `pass-graph.invalid/reference-*`，旧 `duplicate-endpoint`、`source-disabled` 等错误会继续阻止导出直到手动保存；**[中][confirmed]** 任一成功 Runtime cohort 会清空所有 pending-recovery，包括未参与编译的 disabled Graph；**[中][confirmed]** Autosave 只保存 recovery document，不保存 `runtime-rejected` reason，崩溃恢复会把已拒绝 Graph 重新激活并重试。

**Verdict**: NEEDS_CHANGES

## High-level view

Recovery planner 已用 candidate resolution 的同一 `channelEnvironmentRevision` 分类全部 editor 与 recovery document，任一失败都返回 blocked，App 不清 issue、不创建 editor；成功时只创建 reason 为 identity-mismatch 的 recovery editor，既有 dirty editor 的 document、history、selection、generation 与 accepted artifact 均保留。compiler-invalid 在 open/Autosave classification 时优先于 identity mismatch，runtime-rejected recovery 也不会被普通 Pass Graph 编辑提升。

合法 candidate 的 App 提交仍有 **[中][confirmed]** 的 issue 清理不完整：只删除 `pass-graph.invalid` 和 `pass-graph.reference-*`，而 open/Autosave 会把 resolver 的具体 `pass-graph.duplicate-endpoint`、`pass-graph.source-disabled`、`pass-graph.current-cycle` 等写入同一个 project issue 集合。新 candidate 已修复拓扑时这些旧错误仍进入 unified diagnostics，使视觉、fragment 与 Shadertoy 导出继续 fail closed，直到保存成功后 `setProjectGraphIssues([])` 才恢复。

Disabled Graph 保存现在从当前 document、resolved channel environment 与 revision 重新编译 authoring artifact，`saveProjectTo` 再次编译并校验 source、hash、revision 完全一致；enabled Graph 仍必须满足 ready、非 stale、Runtime accepted。disabled Graph 参数保存在 Graph 真源中，已进入 contract 的 Uniform 值随 project metadata/Autosave 保存，reopen roundtrip 已覆盖。

首次持久化 Graph 的 Runtime reject 会记录结构化 reason 并转入只读 fallback，但 **[中][confirmed]** Runtime success 使用全量 `setLoadedGraphPendingRuntimeRecovery({})`。open 会为所有 editable persisted Graph——包括 disabled Graph——设置 pending 后调用 cohort，而 executor 只编译 enabled Graph；空 cohort或不含该 disabled pass 的部分 cohort成功后会误删标记，后续 enable 的首次 Runtime reject只留下 stale editor，不进入预期只读 recovery。

Autosave V2 保存完整 meta、effective accepted sources、Graph documents 与 Pass Graph，并在恢复时重新做 schema、topology、identity 和 compiler classification。**[中][confirmed]** payload 没有 recovery reason/diagnostics；runtime-rejected Graph 在 dirty 状态下被 Autosave 后，恢复只会看到 compiler-valid、identity-valid document，从而创建 editor并再次发起 Runtime cohort，而不是保持崩溃前的只读边界。

真实 fake WebGL harness 经过 `ShadertoyRuntime` 公共 `compile/probePixel/captureAt/endCapture`，现在同一 session 连续执行 frame 0 和 frame 1，断言 capture texture/framebuffer 不重建、ping-pong attachment 翻转、current/previous texture 与内容 label、endCapture 资源释放，以及 preview 恢复原有 next-write 与 previous history。旧 M3 migration、Code↔Graph resolved slot、多边/满槽、导出票据、candidate/effectiveSources 隔离、两帧 preview flip、sampler unit、native capture size 和 preview freeze 的既有回归继续通过。

## 合法 candidate 留下已失效的 topology diagnostics

成功分支只过滤 `issue.code !== 'pass-graph.invalid' && !issue.code.startsWith('pass-graph.reference-')`（`src/App.tsx:1007`）。这是 **[中][confirmed]** 的残留状态错误：`openProjectFrom` 和 Autosave recovery 会按 resolver 原始 code 保存 topology diagnostics；例如旧文档有 duplicate endpoint 时，project issues 可同时包含 reference mismatch 与 `pass-graph.duplicate-endpoint`。编辑为合法 candidate 后 planner 已证明新 resolution 与全部文档可编译，reference issue 被删，但 duplicate endpoint 仍作为 error 进入 `currentExportInput.hasCompileError`。保存会成功并清空 issues，所以数据不会损坏，但用户必须额外保存才能解除已经不存在的导出阻塞。

成功 candidate 应删除所有由旧 Pass Graph snapshot 产生的 `pass-graph.*` project issues，再依赖当前 `passGraphResolution().diagnostics` 表示实时问题；blocked 分支继续保留原 issue。App 级测试需断言 blocked 不清理、合法 promotion 清理、Graph compiler/project 非 topology issue 不被误删。

## Disabled Graph persistence 已闭环，但空 cohort 会消费它的 recovery 标记

`selectGraphPersistenceArtifact` 对 enabled Graph 只接受 `graphCanExport` 的 Runtime artifact；pending/stale、generation/revision 不一致或缺 artifact 都会拒绝。disabled Graph 以当前 resolved environment compile，`saveProjectTo` 再通过 `validateGraphSave` 规范化 document、重算 sourceHash，并按同一 environment 比较 source、hash 与 revision后才原子写入。project I/O roundtrip覆盖 disabled generatedHash、fallback、document 和 identity；enabled 同一 state 无 Runtime acceptance 时仍被拒绝。

**[中][confirmed]** `activatePersistedGraph(..., true)` 会给每个 persisted editable Graph设置 pending，包括 disabled pass；open 的启动条件却按全部 Graph authoring pass 计数（`src/App.tsx:1221-1231`），所以 disabled-only 项目也会调用 `compileGraphCohort`。候选只来自 `enabledGraphPasses()`（`src/App.tsx:593`），但任一 Runtime success 都执行 `setLoadedGraphPendingRuntimeRecovery({})`（`src/App.tsx:648-650`）。空 cohort会消费 disabled 标记，enabled+disabled partial cohort也会删除未参与候选的标记；之后启用该 Graph若 Runtime首次拒绝，代码不会调用 `activateReadOnlyGraphRecovery`。

Runtime success 只能删除本次 candidates 对应的 pending entries，或在 disabled pass enable 时才建立首次 Runtime recovery 标记。测试需覆盖 disabled-only、enabled+disabled、随后 enable并 Runtime reject。

## Autosave 丢失 runtime-rejected recovery 状态

reset、普通 open、compiler-invalid priority、identity promotion、Runtime reject 和 detach 都维护 `graphRecoveryReasonMap`；无关 Pass Graph 编辑也只提升 identity-mismatch。Autosave 是 **[中][confirmed]** 的例外：`AutosavePayload` 只有 `graphDocuments` 与 `passGraph`（`src/project/types.ts:128-137`），`writeAutosave` 也只写这两类 Graph 状态（`src/project/projectIO.ts:401-410`）。恢复统一调用 `activatePersistedGraph(document, options, identityValid)`（`src/App.tsx:1518-1569`），所以先前 runtime-rejected、但 compiler/identity 合法的 document 会被当成 editable persisted Graph，原 reason 与诊断丢失并再次发起 Runtime cohort。

Rejected candidate仍不会直接进入 effective sources，但 crash recovery 改变了只读边界。Autosave payload 应携带逐 pass recovery reason和可呈现诊断；恢复时先应用 compiler-invalid priority，再保持 runtime-rejected readonly，只有 identity-mismatch 进入 repair planner。

## 连续 capture history 已从 helper 提升到公共 Runtime API

fake GL 的 draw label由真实绑定 texture内容生成。两次 preview draw覆盖全局 flip 前后的 current/previous、sampler uniform 0..3、linear/repeat、nearest/clamp和 dummy slots。

同一 capture session 连续执行 frame 0、frame 1；第二次调用不增加 texture/framebuffer或 allocation，Buffer A/B attachment翻转，Buffer B previous label来自 capture A0，Image previous label来自 capture B0，且所有 capture draw都不采样 preview texture。`endCapture` 删除 capture资源与 snapshot但保留 preview资源，下一次 preview draw继续 capture前的 write target和 previous内容。
