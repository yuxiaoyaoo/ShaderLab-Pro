# M2 Graph 闭环基本完成，但 stale 生成代码复制仍混淆 Runtime 接受状态

本轮修复补齐了外部 Pass fallback 再验证、Uniform contract 去重、Graph 保存阻断、Inspector/fragment/画布交互和诊断跳转等 M2 行为。同步 Graph Runtime 编译会接管旧 setup debounce，invalid Graph 则保留 accepted fallback 的外部重验；参数类型切换与 pointer cancel 的 follow-up 也有新增纯函数断言。剩余阻断位于 Generated Code 复制路径：Runtime 拒绝当前 candidate 时，界面复制未接受的 `lastSuccessfulArtifact`，但提示它是上次 Runtime 接受版本。

Watch for: **confirmed** stale Generated Code 的复制内容与成功提示不一致，可能把 Runtime 已拒绝的 GLSL 当作稳定 accepted source 带出应用。

**Verdict**: NEEDS_CHANGES

## High-level view

Graph compile generation 与完整 Runtime setup revision 已分开协调。当前 Graph compile 成功时同步编译会清除旧 debounce 并推进 setup revision；当前 Graph invalid 时，外部 Common、Buffer、Pass config 变化继续用 `runtimeAcceptedArtifact` 作为稳定 Image source，fallback 结果不会被提交为当前 Graph accepted，也不会清除 stale。

RuntimeSetup 按 emitted name 合并 parser 与 Graph uniform metadata，Graph descriptor 覆盖 parser metadata，当前 uniform value 覆盖 default。Inspector draft、参数类型切换、clipboard/fragment 原子校验、registry bounds、焦点和 cancel selection 快照已覆盖此前缺口；Save/Save As 在 M3 前阻断 Graph 项目且不清 dirty。

普通 Code Pass 的 `.frag` 和 Shadertoy package 已共享 stale/pending 门禁。Generated Code 面板仍优先复制 Graph compiler 的最新成功 artifact；该 artifact 可以已经被 Runtime 拒绝，与 stale 时宣称“上次 Runtime 接受版本”的提示冲突。

## Generated Code 在 stale 状态复制未被 Runtime 接受的 candidate

**confirmed** `graphCompileResolved()` 在 Graph compiler 成功后立即更新 `lastSuccessfulArtifact`，而 `graphRuntimeResolved(..., false)` 只把状态设为 stale，不更新 `runtimeAcceptedArtifact`。Runtime 拒绝后，“当前 compiler candidate”和“上次 Runtime accepted artifact”具有不同的信任级别。

`App.tsx:1878` 传给 Generated Code 面板的 source 按 `lastSuccessfulArtifact`、`runtimeAcceptedArtifact` 的顺序选择。`ShaderEditorWorkspace.tsx:49-50` 复制这个 source，并在 stale 时提示“已复制上次 Runtime 接受的生成代码”；实际复制的是刚被 Runtime 拒绝的 candidate。复制内容因此可能与稳定预览不同；没有 accepted fallback 时，提示仍声称存在 accepted source。

该路径应与 `acceptedGeneratedSources()` 使用同一选择规则，在 stale 时只复制 `runtimeAcceptedArtifact.source` 并明确它不是当前 Graph；如果要允许复制当前未接受 candidate，则提示必须明确标记“当前生成但未被 Runtime 接受”。补一个 source-selection 纯测试，覆盖 accepted revision 不同和无 accepted artifact 两种状态。

</details>
