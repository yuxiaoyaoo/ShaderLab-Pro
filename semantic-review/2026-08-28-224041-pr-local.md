# M4 Uniform 契约、导出 ticket 与 Graph 键盘交互收口

M4 将 Code 与 Graph 的 Uniform 合并收敛为单一 Runtime contract，并以 runtime setup revision 和 Graph accepted artifact 建立统一导出 ticket。Graph authoring 增加 generated fragment 与 Graph JSON 导出，AI/模板应用在 Graph 模式下 fail closed，节点画布补充键盘操作与 RAF pointer batching。剩余阻塞点是 EditorPane 文本导出未绑定原始 ticket、标量 Uniform 类型切换无法可靠重置旧值，以及节点本体的 Enter 行为没有兑现键盘连线契约。

Watch for: **confirmed** — EditorPane 的 `.frag` 与 Shadertoy JSON 在状态变化后重新 ready 时会放行先前快照；**confirmed** — float/int 声明切换时，整数数值会被误认为新类型兼容并保留；**confirmed** — 聚焦 GraphNode 后 Enter 只选择节点，只有 Space 会启动输出连线。

**Verdict**: NEEDS_CHANGES

## High-level view

视觉导出、App 菜单 Shadertoy 导出和 Graph generated fragment 都保存并复核同一个 ticket；EditorPane 的 `.frag` 与 Shadertoy 导出只查询复核时的 eligibility，无法识别从 ready 经修改再回到 ready 的 ticket 更替。

Uniform conflict 的全局 namespace、诊断 origin 和 Graph metadata 优先级已经收敛。值 reconcile 没有上一版 declaration/type，因而无法区分 JS number 曾属于 float 还是 int，类型变化不一定采用新 default。

GraphCanvas 的主要键盘路径已经建立，但 roving focus 落在节点本体时，Enter 与 Space 行为不一致：只有 Space 进入输出连接模式。

## EditorPane 文本导出没有复核捕获 ticket

**Medium — confirmed.** `saveActiveFrag` 在目录选择前读取 effective source，`saveShadertoyJson` 同样先生成 JSON；目录选择返回后，`saveToFolder` 只调用 `validateExport?: () => string | undefined`（`src/components/EditorPane.tsx:105-117,125-146`）。App 传入 `currentExportEligibility().reason`（`src/App.tsx:2188`），没有携带启动时的 `ExportTicket`。runtime setup 若在等待期间从 ticket A 变化到 ticket B 并重新 ready，复核没有错误，旧 source/JSON 快照仍会写出。App 菜单 Shadertoy 路径使用同一捕获 ticket 复核（`src/App.tsx:1158-1179`），两条路径行为不对称。

让 EditorPane 在构造内容前捕获 ticket，并在最终写入前用同一 ticket 调用 `validateExportTicket`；或把 `.frag`/Shadertoy 的完整 guarded export callback 放回 App。增加 ready(A) → picker wait → ready(B) 测试并断言零 `writeTextFile` 调用。

## Uniform 标量类型切换保留旧声明值

**Medium — confirmed.** `reconcileUniformValues` 只有当前 declaration 与无类型值，并直接调用 `isUniformValueCompatible`（`src/shadertoy/uniformContract.ts:72-82`）；生产 effect 也只传当前 declarations 和 values（`src/App.tsx:360-362`）。float 和 int 都是 JS number，因此旧 `float u = 1` 改为 `int u = 4` 时实际返回 `{u:1}`，而不是新 default 4；int → float 也总会保留。`verify-m4` 只用非整数 `3.2` 检查 int，不覆盖声明类型变化（`scripts/verify-m4.mjs:35-39`）。

给 reconcile 传入上一版 declaration/type map，只有 runtime type 未变且当前值对该 shape 合法时才保留；类型变化一律使用新 default。补充 float(1) → int(default 4)、int(1) → float(default 0.5) 和同类型保留测试。

## GraphNode 的 Enter 没有启动输出连线

**Medium — confirmed.** `GraphCanvas.onNodeKeyDown` 对 Enter 只更新 selection 后立即 return；启动首个输出连接的分支只处理 Space（`src/components/graph/GraphCanvas.tsx:130-136`）。输出 socket 按钮本身支持 Enter/Space，但 roving focus 的落点是节点本体，因此节点级 Enter 路径缺失。

将节点本体 Enter 与 Space 归一到同一个 `startKeyboardConnection` intent，并保留 default/propagation 抑制。纯 helper 或组件测试应断言两种键产生相同 connection state，而不只测试 `beginKeyboardConnection` 数据函数。
