# M2 Graph 编辑闭环基本成形，但类型切换与取消手势仍会提交无效状态

本轮修复已把 accepted fallback、Uniform contract、Graph 保存阻断和导出门禁接到统一执行路径，旧报告中的大部分集成缺口已经闭合。Runtime fallback 只在当前 generation 的成功 artifact 上提交，旧 accepted source 仅用于稳定预览再验证。Inspector 参数类型切换和 pointercancel 仍违反明确契约，Graph 同步编译也没有作废已排队的通用 debounce；验证脚本未覆盖若干明确要求的边界。

Watch for: **confirmed** 颜色参数切成标量后会保留不兼容的 color widget，使 Graph 无法通过自身 schema；**confirmed** pointercancel 不会撤销 pointerdown 已提交的 selection；**confirmed** Graph 同步 Runtime compile 后旧 debounce 仍会再次编译。

**Verdict**: NEEDS_CHANGES

## High-level view

外部 Pass 修改现在会用 current-success 或 accepted fallback Image 重建完整 setup，fallback 结果不会提升为当前 Graph accepted，也不会清除 stale。Graph 的同步 Runtime 编译与通用 setup debounce 仍是两套未互相作废的调度路径，同一最新 setup 可能被重复编译。

Uniform contract 已按 emitted name 合并，Inspector draft 也阻止了非有限值、非整数和错误向量进入文档。参数类型切换只替换类型和默认值，没有同步修正依赖类型的 UI metadata，仍能生成 schema-invalid Graph。

画布 bounds、诊断 reveal 和 Graph 快捷键焦点已改用共享几何与明确 scope。取消手势仍保留 pointerdown 阶段的 selection 变化，且这条生命周期约束没有纯逻辑测试。

M3 正式 Graph 项目文件读写仍按要求留待后续；当前 Save/Save As 保持阻断且不清 dirty。

## High — 参数类型切换保留不兼容 widget，产生不可恢复的 Graph

**confirmed** `src/components/graph/GraphInspector.tsx:69` 在参数类型变化时只提交 `{ valueType, defaultValue: defaultGraphValue(valueType) }`。已有 `ui` 完整保留，因此一个 `{ valueType: 'color3', ui: { widget: 'color' } }` 参数切到 `float` 后会变成 `float + color widget`；`src/graph/schema.ts:234-237` 明确拒绝这个组合。

编辑器内存中的 Graph 仍会继续编译并把 `widget: 'color'` 发进生成 Uniform metadata，但 autosave 恢复会调用 `normalizeGraphDocument()` 并拒绝该文档，随后把 Image authoring 降为 Code。类型切换应原子生成与新类型兼容的 `defaultValue` 和 `ui`：标量/布尔离开 color widget，必要时重置范围与 step，并增加 schema round-trip 测试。

## Medium — pointercancel 仍保留 pointerdown 的 selection 提交

**confirmed** `src/components/graph/GraphCanvas.tsx:82` 在节点 pointerdown 立即提交选择，`:116` 在空白画布 pointerdown 立即清空选择。`:192-198` 的 `cancelPointer()` 只清 drag、pan、box、connection transient，不恢复手势开始前的 selection，所以系统取消、失去 capture 或触控取消后，节点选择/取消选择和画布清空仍然生效。

这不满足“pointercancel 只清 transient，不提交 move/pan/selection/connection”。应在手势状态中保留起始 selection，并将 click/box selection 延后到成功 pointerup，或在 cancel 时恢复快照；纯 helper 需要覆盖节点点击取消、修饰键取消选择后取消、空白框选取消三种路径。

## Medium — Graph 同步编译没有作废旧 setup debounce

**confirmed** `src/App.tsx:396-420` 的 `compileGraphGeneration()` 直接同步调用 Runtime，但没有清除 `debounceTimer` 或递增 `runtimeSetupRevision`。只有 `scheduleCompile()` 在 `:495-504` 会执行这两个门禁动作，因此 Graph compile 已使用最新 Common/Buffer/config 完成后，之前排队的通用请求仍会在稍后重新读取 candidate 并再次编译。

当前同步 Runtime API 下，这通常表现为重复重建资源和重复覆盖 diagnostics，而不是提交错误 artifact，但仍违反“Runtime compile 同步但仍避免旧 debounce”。同步 Graph compile 应显式接管 setup revision、取消旧 timer，并把 compile state 收敛到 ready；调度 coordinator 需要同时验证 fallback 不提交与同步 compile 作废旧 request。

## Low — verify:m2 未覆盖完整拒绝矩阵与 setup 构造

**confirmed** `scripts/verify-m2.mjs` 没有重复 edge ID、重复 parameter ID 的 clipboard/insert-fragment 断言，也没有直接调用 `buildRuntimeSetup()` 验证 stable Image fallback 与外部 Pass/config 组合后的 setup。pointercancel 没有纯 helper，因此也没有验证 cancel 对 move、pan、selection、connection 均为零提交。

现有 `verify:m1`、`verify:m2`、`typecheck` 和 `build` 均通过，build 只有既有的大 chunk 警告；这些成功结果没有覆盖上述边界。
