# Image Shader Graph 编辑器已接入，但 Runtime 上下文与持久化边界仍不闭合

本次变更把 Image Pass Graph 编辑器、command/history、诊断跳转、Generated Code 和 candidate→Runtime accepted→stale 状态机接入现有工作台。Graph 语义修改使用 generation 门禁和 debounce，布局修改不触发编译，Runtime 拒绝 candidate 时保留旧预览。集成层仍会冻结外部 Pass 验证、重置 Graph 参数、丢失已保存 Graph，并允许 stale 项目从次级入口导出；画布、Inspector 和剪贴板也有会破坏 M2 基本操作契约的缺口。

Watch for: **confirmed** 当前 Graph 无效时 Common/Buffer/Pass 配置不再送 Runtime 验证且诊断停留在旧结果；**confirmed** Graph Uniform 被重复注册并在重编译时用 artifact 默认值覆盖当前值；**confirmed** 项目保存会标记 clean 却不写 Graph，重开后静默变成 Code；**confirmed** Code Pass 工具栏可绕过 stale 导出门禁。

**Verdict**: NEEDS_CHANGES

## High-level view

Graph store 用 Graph generation 拒绝过期 Graph 编译结果，并区分最后生成成功与 Runtime 接受 artifact；外部 Code/Common/Buffer 变化却没有独立 setup revision。当前 Graph 编译失败后，外部变化直接跳过 Runtime，accepted artifact 没有作为稳定预览的再验证输入。

`effectiveSources` 为 Graph Image 选择 Runtime accepted GLSL，主导出按钮也依赖 stale 状态。项目保存、Autosave 恢复和 EditorPane 内的 Shadertoy 导出没有共享这个边界：常规保存缺 Graph 文件，Autosave 缺 accepted fallback，次级导出缺 stale 门禁。

Graph 参数既从生成 GLSL 重新解析，又从 artifact metadata 追加到 Runtime setup。重复 emitted name 使重编译回到 Graph 默认值，Uniform Inspector 当前值与画面脱节。

画布 cancel 与正常 pointer-up 共用提交路径，修饰键取消选择仍按旧选择集启动拖动，鼠标选择也不会可靠地把快捷键焦点交给 Graph pane。框选与 Fit All 假定固定节点高度，与多 Socket 节点不符。

Inspector 和剪贴板会把不满足 schema/引用约束的数据写入文档。诊断 reveal 不会退出 Generated Code，本应替换当前 Image Code 的创建操作也缺少确认。

## 无效 Graph 会冻结 Common、Buffer 与 Pass 配置验证

**confirmed** `scheduleCompile()` 在 `src/App.tsx:498-503` 只使用 `graphState.latestResult.artifact`；Graph 结构或类型错误使 `graphSemanticChanged()` 清空 `latestResult` 后，Common/Buffer 源码、启用状态、channel 或 feedback 修改都会进入 `if (!candidate) return`。旧 `runtimeAcceptedArtifact` 仍可作为稳定 Image 输入，却没有参与完整 setup 再验证。

外部 Pass 新错误不会产生诊断，旧 Code 诊断也不会刷新；修复同样无法验证。最小修复是分离 Graph candidate revision 与完整 Runtime setup revision，外部变化始终用 `latestResult.artifact ?? runtimeAcceptedArtifact` 组装候选；结果仅在 Graph generation 和 setup revision 都匹配时提交，Graph 自身无效时继续保持 stale。

## Graph Uniform 重复注册会在重编译时覆盖当前值

**confirmed** `runtimeSetup()` 与 `runtimeSetupForGraphArtifact()` 在 `src/App.tsx:344-347,383-390` 先对生成 GLSL 调用 `parseUniforms()`，再追加 `artifact.uniforms`。Emitter 已输出 uniform 声明；实测默认 `0.75` 的 Graph Parameter 被 parser 解析为默认 `0`，合并数组含两个相同 emitted name。

`ShadertoyRuntime.compile()` 在 `src/shadertoy/runtime.ts:567-570` 将数组转成 Map，后追加的 artifact 默认值覆盖 `uniformValues()` 当前值，相关重编译都会重置参数。最小修复是只建立一次统一 contract：Code 由 parser 提供，Graph 由 artifact 提供，按 emitted name 检查类型并去重，value 优先取当前值、缺失时才取 artifact default。

## “保存成功”没有保存 Graph，恢复也没有 accepted fallback

**confirmed** `saveProject()`/`saveProjectAs()` 在 `src/App.tsx:789-814` 把 `effectiveSources()` 交给 `saveProjectTo()`；`src/project/projectIO.ts:47-76` 只写 config 和 `passes/*.glsl`，不写 metadata 指向的 `graphs/image.shadergraph.json`，随后仍清 dirty。重新打开时 `src/App.tsx:753-756` 直接把 Graph authoring 改成 Code，没有错误或确认，节点、边、参数和布局静默丢失。

**confirmed** Autosave 附带 Graph document，却保存原始 `sources()` 而非 runtime-accepted generated fallback。当前 Graph 无效时恢复出的 store 没有 accepted artifact；Inspector 产生的 NaN 还会被 JSON 改成 `null`，normalize 失败后回到创建 Graph 前的旧 Image Code。最小安全修复是在完整持久化落地前禁用 Graph Save/Save As 且不清 dirty，或同步保存 Graph、accepted generated source/hash 与 Code fallback；缺失或损坏时只能显式只读恢复，不能静默转 Code。

## Code Pass 工具栏绕过 stale 导出门禁

**confirmed** 顶部导出与 `App.exportShadertoyJson()` 检查 `graphCanExport()`，但 active tab 为 Common/Buffer/Sound 时会渲染 `EditorPane`；其 `saveShadertoyJson()` 在 `src/components/EditorPane.tsx:128-137,295-297` 直接调用 `props.shadertoyJson()`。Graph invalid、pending 或 Runtime-rejected 时，切到 Code Pass 仍能导出包含旧 accepted Image 的包。

最小修复是移除重复整包入口，或把统一 capability 传给所有导出动作；门禁必须在执行函数中再次检查，不能只依赖 disabled 按钮。

## Inspector 可以把非有限值和错误向量写进 GraphDocument

**confirmed** `GraphInspector.parseValue()` 在 `src/components/graph/GraphInspector.tsx:12-14` 对标量直接 `Number(raw)`、对向量直接 `split(',').map(Number)`，Parameter 默认值同样处理。`abc` 产生 NaN，错误分量数也直接提交；Autosave 的 JSON 序列化随后把 NaN 改成 `null`。

最小修复是在 Inspector 保持独立文本 draft，只在 finite、整数约束和分量数满足字段类型时提交；无效 draft显示内联错误但不进入 GraphDocument。Parameter widget/min/max/step 应复用同一 schema-aware editor。

## 外部剪贴板可插入缺失 Parameter 引用，command 也允许 dangling fragment

**confirmed** `parseGraphClipboard()` 在 `src/graph/editor/clipboard.ts:27-32` 只做 schema normalize；`pasteGraphSelection()` 在 `:40-44` 找不到参数映射时保留原 ID。实测 `parameterId: "missing"` 且 parameters 为空的 payload 会被接受并插入，使整图 stale。

**confirmed** `insert-fragment` 在 `src/graph/editor/commands.ts:37-46` 只检查与现有 ID 碰撞和 Output 节点，没有检查 fragment 内重复 ID、edge endpoint/socket、重复输入或 Parameter 引用。最小修复是先验证 payload 自洽，再在合并后的克隆上执行结构验证，失败时原子拒绝整个 command；补缺参数、dangling edge、内部重复 ID 和完整 undo 回归。

## Pointer cancel 和修饰键取消选择会提交错误拖动

**confirmed** `GraphCanvas.onNodeDown()` 在 `src/components/graph/GraphCanvas.tsx:31` 对已选节点 Ctrl/Shift 点击时先删除 selection，却仍从修改前选择集建立 drag positions，轻微移动就会提交已取消节点组的位置。

**confirmed** 根元素在 `src/components/graph/GraphCanvas.tsx:39` 把 `onPointerCancel` 绑定到 `onPointerUp`，cancel 会提交 transient positions、viewport、框选或连接。最小修复是按最终 selection 决定是否启动 drag，并拆出只清理 transient state 的 cancel 路径；Socket down 也只应接受主键。

## 画布选择后快捷键焦点没有可靠进入 Graph pane

**likely** `GraphEditorPane` 仅在其 DOM 子树有焦点时通过 `onKeyDown` 处理 Delete、Copy/Paste、Duplicate 和 Undo/Redo（`src/components/graph/GraphEditorPane.tsx:25-27`）。Canvas/pane 虽有 `tabindex=0`，节点、grid 和 socket handlers 没有调用 `focus()`；鼠标选中非 focusable 后代后，Graph handler不会可靠收到按键，Space 还可能进入 App 全局播放处理。

最小修复是在画布主键 pointerdown 显式 focus workspace，并按 focus scope 分派 Graph 与 App 快捷键；补“鼠标选节点后 Delete/Ctrl+C/Ctrl+Z”和 Inspector 输入不穿透的浏览器测试。

## 固定 118px 节点高度使 Fit All 和框选漏算多 Socket 节点

**confirmed** `GraphCanvas` 在 `src/components/graph/GraphCanvas.tsx:14,28,35` 用固定 `NODE_HEIGHT = 118` 计算 Fit All、reveal 与框选相交，节点 CSS 高度却随 Socket 行数变化；四输入节点约 148px，底部区域无法正确命中且可能被 Fit All 裁切。

最小修复是从 DOM bounding box 建立 graph-space bounds，或由 registry 计算每节点高度；fit、reveal 和 hit-test 必须使用同一 bounds。

## 诊断跳转不会离开 Generated Code 视图

**confirmed** `App.jumpTo()` 在 `src/App.tsx:992-1001` 更新 tab、selection 和 `revealNodeId`，但 `ShaderEditorWorkspace.view` 是内部 signal，只在 authoring 变回 Code 时重置（`src/components/ShaderEditorWorkspace.tsx:14-18`）。停在 Generated Code 点击节点诊断时，GraphCanvas 仍未挂载。

最小修复是提升 view 状态，或在 `revealNodeId` 变化时先 `setView('graph')` 再 reveal。Generated Code textarea 的 readonly 属性本身没有可编辑绕过。

## 创建 Graph 缺少替换当前 Image Code 的确认

**confirmed** `createImageGraph()` 在 `src/App.tsx:456-469` 验证默认图后直接把 Image authoring 改成 Graph；唯一 `window.confirm` 位于项目级离开流程（`:696`）。原 Image Code 暂留在 `sources()`，但 UI 无恢复入口，Detach 会用 generated GLSL 覆盖它。

最小修复是在 candidate 编译前明确确认不会反编译且 Detach 会替换 Code；取消不得改变 Runtime、meta 或 dirty，并保留可显式恢复的 Code backup。
