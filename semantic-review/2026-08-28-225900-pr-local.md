# M4 Graph Uniform 冲突门禁与 Autosave 恢复

M4 用 `currentUniformConflict()` 合并 accepted Uniform contract 与当前 Graph state diagnostics，补上上一轮 Graph candidate 冲突绕过 autosave 的问题。Graph accepted A 后，candidate B 的 `uniform.type-conflict` 会在写盘前阻止手动保存、另存为、autosave 和所有 runtime-derived 导出。B 再次 semantic change 时会清除旧 runtime diagnostics；即使全局 diagnostics 暂存上一轮冲突，autosave 也能恢复。模板边界、导出 ticket 冻结和 Graph ARIA/键盘路径均通过复核。

Watch for: Graph JSON 仍有意允许导出当前 authoring 真源；它不包含 accepted GLSL，不属于混合快照或 runtime-derived 导出。

**Verdict**: APPROVED

## High-level view

Uniform 冲突查询只读取顶层 accepted contract diagnostics 和当前 Graph editor state 的 compile/runtime diagnostics。它既能看到尚未 accepted 的 candidate 冲突，又不读取可能滞后的全局 `diagnostics()`。

保存与 autosave 在构造持久化快照前执行门禁，`currentGraphSaveOptions()` 在实际保存参数求值时再次复核。冲突状态不会调用项目原子保存或 autosave 写入，因此不会形成“当前 Graph B + accepted GLSL A”的混合快照。

Runtime-derived 导出通过 `currentExportInput()` 接收同一冲突状态，并由冻结 ticket 在目录选择、逐帧捕获和最终写入边界复核。Graph JSON 是只含当前 authoring document 的独立备份路径。

Graph 模板 preflight 仍先于项目 mutation；自定义模板在后端调用前和异步返回后的提交点都 fail closed。节点、socket、Inspector 与 modal 的 ARIA 标注及 Enter/Space 键盘连线路径保持完整。

## Candidate Uniform 冲突在混合快照边界 fail closed

`uniformContract()` 代表 Runtime accepted artifact，`currentUniformConflict()` 额外查询当前 Graph state 的 `graphDiagnostics()`。accepted A 保持预览 fallback 时，candidate B 在 `compileGraphGeneration()` 中产生的 `uniform.type-conflict` 会进入 B 的 `runtimeDiagnostics`，无需替换 accepted artifact 即可触发门禁。

`saveProjectAs()` 在目录选择前拒绝冲突，并在异步选择返回后通过 `currentGraphSaveOptions()` 再次复核；`saveProject()` 在 `saveProjectTo()` 前拒绝，`runAutosave()` 在读取 Graph document 和 accepted effective sources 前返回。这些路径不会到达 `saveProjectTo()`、`writeAutosave()` 或底层原子写入。

`currentExportInput()` 将冲突映射为 `hasUniformConflict`。App 菜单、EditorPane 文本和视觉导出均先取得 eligibility/ticket，并在实际写盘前复核原 ticket；冲突 B 无法获得新 ticket，也无法继续使用旧 ticket。

## Semantic change 释放 Autosave 而不放宽 stale 保存

`graphSemanticChanged()` 清空 `latestResult` 和 `runtimeDiagnostics` 并增加 generation。B 的下一次 semantic edit 会移除上一轮 candidate conflict；后续普通 compiler-invalid 只进入当前 `latestResult.diagnostics`。由于 `currentUniformConflict()` 不读取全局 `diagnostics()`，authoring autosave 可以恢复。

普通 compiler-invalid 仍使 Graph stale：`currentGraphSaveOptions()` 拒绝手动保存，`currentExportInput()` 也因 compile error/stale 状态拒绝 runtime-derived 导出。恢复范围仅限用于故障恢复的 Graph authoring autosave。

## 回归验证

内置 Graph 模板仍在 `confirmUnsaved()` 和状态 mutation 前运行 compiler preflight；自定义模板在 `adoptTemplate()` 前检查 Code authoring，并由 `applyAiCode()` 在异步返回后复核。Ticket 继续以 `Object.freeze()` 固定 Runtime revision、authoring、Graph generation、artifact revision 和 source hash。Graph canvas application 描述、节点/socket label、Inspector 的 `aria-invalid`/alert、modal label 与节点 Enter/Space 连线 intent 均仍接入生产路径。

`npm run verify:m4`、`npm run typecheck`、`npm run build` 和 `cargo test --manifest-path src-tauri/Cargo.toml` 均通过；Rust 共运行 46 个测试。额外状态断言覆盖 accepted A、冲突 candidate B、再次 semantic change 清除 runtime diagnostics，以及普通 compiler-invalid 保留 accepted A 的迁移。
