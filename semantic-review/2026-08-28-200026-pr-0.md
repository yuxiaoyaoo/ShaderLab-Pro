# Shader Graph M1 编译核心与后续里程碑边界

这次变更建立了无 UI 的 Graph schema、Registry、结构验证、类型推导、GLSL 生成、source map 和统一诊断，并补上 M0 的 `effectiveSources` 接入边界。全图结构校验与仅对 Fragment Output 可达节点做类型推导/发射的分层已经形成，节点顺序、边顺序和 viewport 也不会改变当前有效样例的输出。当前仍有四个必须在 M1 固化的契约缺口，其中节点值未按节点定义验证已经能让编译器成功返回语法非法的 GLSL；另外三个会让 M2–M6 的错误映射、优化和参数状态建立在不稳定接口上。

Watch for: **confirmed** 节点 `values` 可绕过类型契约并生成非法 GLSL 或被静默改值；**confirmed** Typed IR 只是 GLSL 字符串的旁路快照；**confirmed** source map 没有绑定 `sourceHash`/artifact revision；**confirmed** uniform 碰撞序号会改写既有参数的 emitted name。

**Verdict**: NEEDS_CHANGES

## High-level view

结构门禁覆盖整张图的重复 ID、未知定义、Socket、悬空边、重复输入和环，而类型推导与发射只处理 Output 反向可达子图。这个边界符合 M1 设计，但 schema 只确认 `values` 是 JSON-safe 数据，没有确认它满足具体节点契约。

节点定义直接返回 GLSL 表达式，编译器拼接临时变量和行映射后才构造一个仍含 `expression: string` 的 Typed IR。IR 不参与最终发射，后续常量折叠、CSE、Node Group 和 Custom Function 无法在不解析 GLSL 字符串的前提下实现。

source map 只携带 pass 和行区间，诊断转换也只按 pass 选择 map。当前 store 没有保留最后成功 artifact revision 和 stale 状态，无法证明诊断、预览和导出对应同一次 Graph 编译。

GLSL 与 semantic hash 的主要排序路径是确定的，float 到向量的 splat 在固定 Socket 和通用 numeric 节点上也会落成显式构造。参数名称碰撞却使用排序后的递增序号，加入一个更早排序的同名参数会让未修改参数的 emitted name 整体后移。

## 节点 values 绕过 schema 并可生成非法 GLSL

**confirmed** `normalizeGraphDocument()` 在 `src/graph/schema.ts` 对节点 `values` 只调用 `jsonSafeFiniteTree()`；`NodeDefinition` 在 `src/graph/registry.ts` 没有 value schema 或 validator，因此 `value.float.value` 的字符串、错误维度的向量和非字符串 swizzle 都是合法文档。类型阶段只读取 Socket 类型；`emitLiteral()` 会把错误 float 静默降为 `0.0`，使加载后的 Graph 偏离持久化数据。

`vector.swizzle` 的 `inferTypes()` 在 mask 不是字符串时回退到 `xy`，但 `emit()` 对原值做 `String()`；`mask: 12` 会返回 `ok: true`、无诊断并生成：

```glsl
vec2 _sg_n1_out = (_sg_n0_out).12;
```

`scripts/verify-m1.mjs` 只断言生成文本和纯函数结果，没有把 artifact 交给 WebGL2/GLSL 编译器。最小正确修复是在 `NodeDefinition` 增加声明式 value schema 或 `validateValues`，在可达性裁剪前对所有节点执行；通用 Socket 默认值按 `GraphValueType` 检查，`parameterId`、swizzle 等配置字段由节点定义检查，并禁止未知字段或明确规定迁移策略。补充 malformed-value fixture 和至少一组通过现有 Runtime/WebGL2 编译的 Graph→GLSL smoke test。

## Typed IR 是发射后的字符串影子

**confirmed** `IrValue` 在 `src/graph/compiler/ir.ts` 以 `expression: string` 保存 GLSL，`NodeDefinition.emit()` 在 `src/graph/registry.ts` 也直接返回 `Record<string, string>`。`compileGraph()` 在 `src/graph/compiler/index.ts` 先调用节点 GLSL emitter、填充 `bodyLines` 和 `expressionMap`，随后构造 `irNodes`；`createTypedIr()` 之后只检查节点数量，最终 `emitSource()` 消费的仍是之前拼好的 `lines`。

后续优化即使修改 IR 也不会影响输出，source map 只能继续绑定手工拼接的行。最小正确修复是让节点定义 lower 到带判别联合的 typed expression/instruction（literal、uniform、builtin、unary、binary、call、construct、convert、swizzle），把 float splat 表示成 conversion IR；GLSL emitter 只遍历 Typed IR 生成 helper、声明、表达式和 source map。

## Source map 没有 artifact 身份，无法证明映射新鲜度

**confirmed** `GraphSourceMap` 在 `src/graph/compiler/sourceMap.ts` 只有 `pass` 和 `entries`，`sourceHash` 仅作为 `GraphCompileResult` 的平级字段存在。`fromRuntimeDiagnosticWithGraphSourceMap()` 在 `src/diagnostics/model.ts` 只检查 pass 后按行查找；Runtime `CompileResult` 不携带 Graph revision，`src/state/projectStore.ts` 与 `editorStore.ts` 也没有最后成功 Graph artifact、pending revision 或 stale-preview 状态。

同一 pass 的任意旧诊断都能被当前 map 接收，无效 Graph 也没有可验证的“预览来自哪个成功 revision”。最小正确修复是引入 `GraphArtifact { revision, semanticHash, sourceHash, source, sourceMap, uniforms }`，让 map 内含并校验相同的 `sourceHash`/revision；Runtime 请求和结果保留 artifact revision，诊断仅在 revision 精确匹配时映射。store 记录 requested、last-successful 和 runtime-accepted revision，导出只接受三者一致且当前 Graph 无错误的 artifact。

## 同名参数的序号碰撞会改写既有 uniform 名称

**confirmed** `makeUniforms()` 在 `src/graph/compiler/index.ts` 按合法化 display name 和 parameter ID 排序，再分配 `_sg_u_main`、`_sg_u_main_2` 等序号。已有参数 `a`/`b` 分别得到 `_sg_u_main`/`_sg_u_main_2` 时，新增排序更早的同名参数 `0` 会使它们变成 `_sg_u_main_2`/`_sg_u_main_3`，尽管 `a`、`b` 未变化。

输出仍可重复，但名称不具备增量稳定性，参数编辑会造成不必要的 uniform 状态重建和 source-hash 级联变化。最小正确修复是从稳定 parameter ID 导出固定消歧后缀，例如合法化 display name 加 ID 的确定性短 hash；若重命名也必须保持 shader-level identity，则 emitted name 完全由 ID 生成，display name 只保留在 `GeneratedUniform` 元数据中。增加“插入/删除碰撞参数不改变其他 ID→name 映射”的测试。
