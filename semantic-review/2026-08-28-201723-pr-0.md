## High-level view

节点持久化值现在经过两层可组合门禁：输入 socket 先按具体类型或 `defaultType` 检查，节点声明的 `valueFields` 再施加字段专属约束。节点省略字段仍被允许，但显式值、节点默认值和 socket fallback 都不能绕过 bool/int/float/vector/color 的形状与 finite 约束。

编译器按完整拓扑推导输入输出类型，因此不可达子图中的非法 swizzle 也会阻止编译并返回空 source。可达集合只控制 uniform 收集、IR lowering 和 emission，保留死代码裁剪而不放宽持久化 Graph 的语义完整性。

`npm run verify:m1`、`npm run typecheck` 和 `npm run build` 均成功；200 节点 DAG 验证平均 2.47 ms、最大 3.58 ms。生产构建只有既有的大 chunk 提示。本轮未修改或重新归因 App/UI/项目 IO 基线差异。

## Socket 基础 validator 与节点专属约束叠加

`validateNodeValues()` 会为输入字段同时组装具体/default `GraphValueType` validator 与 `valueFields` validator，并在任一层失败时产生稳定的 `graph.invalid-node-value`。自定义 validator 即使接受值，float socket 仍拒绝字符串，向量和颜色仍检查分量数与 finite，int 仍检查整数。

`NodeRegistry.register()` 分别把 `defaultValues` 与每个 `SocketDefinition.defaultValue` 送入同一校验路径。新增测试构造宽松自定义 validator 和字符串 float fallback，确认前者不能覆盖基础规则、后者不能完成注册。

## 不可达 swizzle 仍受类型语义约束

结构验证后，编译器对完整 topological order 建立 input/output type；该阶段无诊断时才过滤出 Output 反向可达节点进行 lowering。`vector.swizzle` 先拒绝非字符串、混合命名组及非法长度，再根据实际输入维度拒绝越界分量，因此 `vec2.z` 无论是否可达都会产生 `type.inference-failed` 并返回 `source: ''`。

回归测试保留可达非法 mask 的覆盖，并新增不可达 `vec2 -> swizzle.z` 图；两条路径都在 emission 前失败。
