## High-level view

Pass Graph candidate 按同一个 resolved channel environment 对 editor 与 recovery document 做全量分类。blocked candidate 保留旧 project issues；只有全量可提升的 candidate 才删除全部 `pass-graph.*` snapshot issue，因此旧 topology error 不再污染已修复状态，失败编辑也不会擦除恢复证据。

首次 Runtime recovery 标记现在以 accepted enabled Graph pass 集合为清理边界。partial cohort 不触碰 disabled 或未参与 pass，empty cohort 保留全部标记；后续启用并首次被 Runtime 拒绝时仍会进入只读 generated-GLSL fallback。

Autosave V2 保存 recovery reason/diagnostics，并在写入时让 metadata reference 指向 snapshot 自己的 Pass Graph revision。读取端白名单化 pass、reason、severity、stage 与 graph-local origin；恢复端重新执行 schema、topology、identity 与 compiler 分类，compiler-invalid 覆盖持久化 reason，只有仍 compiler-valid 的 runtime-rejected document 保持只读边界。

保存与导出仍依赖同一 resolved revision 和 Runtime accepted cohort：enabled Graph 不能用 stale 或仅 authoring-compiled artifact 保存，disabled Graph 可用 exact environment 的确定性 compiler artifact，导出继续由 diagnostics、cohort identity、runtime revision 与 effective-source hash 共同 fail closed。真实 Runtime capture 仍把 preview 与 capture feedback history 隔离，并在同一 session 内连续复用和翻转独立 ping-pong 资源。

## Pass Graph promotion 同时更新 topology 与 recovery identity

`planPassGraphIdentityRecovery` 用 candidate、project 和全部 editor/recovery 文档建立一个 resolution，再按该 revision 逐 pass 编译。任一 topology 或 document 失败都会 blocked，且 `updatePassGraph` 不清 `projectGraphIssues`；成功分支才过滤全部 `pass-graph.*` issue，并只提升 `identity-mismatch` recovery。runtime-rejected 与 compiler-invalid 因此保持只读，旧 `duplicate-endpoint`、`source-disabled`、cycle 等 snapshot 诊断则不会继续阻止已修复 candidate 导出。

Autosave 写入前通过 `projectWithPassGraphIdentity` 让 metadata reference 指向快照内的 Pass Graph revision。恢复仍重算 reference issues；metadata、Pass Graph 或 documents 被篡改或部分损坏时会重新建立 identity/topology diagnostics，保存的 recovery reason不能绕过解析和编译。

## Runtime recovery 标记按 accepted cohort 消费

`compileGraphCohort` 要求 candidates 与当前全部 enabled Graph passes 一一对应，Runtime 成功后才把这个集合交给 `clearAcceptedRuntimeRecoveryFlags`。helper 只删除传入 pass，所以 enabled+disabled 项目的 disabled 标记、disabled-only open 的 empty cohort标记都会保留；后续 enable首次 Runtime reject仍转换为 `runtime-rejected` readonly recovery。

已有 accepted artifact 的普通编辑失败继续使用 M2 stale-preview；只有持久化 Graph 尚无 Runtime accepted artifact时才触发首次加载 fallback，修复没有扩大只读恢复范围。

## Autosave recovery metadata 保持 fail-closed

`AutosavePayload.graphRecovery` 是可选兼容字段，旧 V2 与 source-only legacy payload无需迁移。normalizer只遍历 `image` 与四个 buffer，限制 reason、severity、stage，并把 origin强制重建为 map key对应的 Graph origin；未知 pass、伪造 code origin、非法枚举和非数组 diagnostics不会进入 App 状态。

`doRecover` 对实际解析出的 authoring document重新做 exact-environment compilation：失败立即进入 `compiler-invalid`，有效时才恢复 runtime-rejected readonly及其 diagnostics；identity-mismatch 与 compiler-invalid reason由当前快照重推导而非盲信。缺失 document仍产生 `graph.missing`、降低 editable count并保留 generated GLSL fallback，recovery metadata不能创建虚假 editor。

## 保存、导出与连续 capture 门控保持不变

成功 candidate仅清旧 `pass-graph.*` project snapshot；当前 `passGraphResolution().diagnostics` 和 recovery diagnostics仍进入 unified diagnostics。保存继续要求 editor、有效 resolution及 enabled Graph Runtime acceptance，导出另要求 runtime revision、artifact identity、Pass Graph revision和 effective source hash一致。

连续 capture回归通过 `ShadertoyRuntime` 公共 API在同一 session执行 frame 0与1，覆盖资源复用、attachment翻转、current/previous内容来源、preview/capture texture隔离、结束释放及 preview history恢复。M0–M5、TypeScript、生产构建与Rust原子写/回滚测试全部通过；既有 migration、endpoint/slot、cohort、disabled roundtrip、identity、导出票据、native尺寸、preview freeze、sampler和两帧 timing回归保持关闭。
